# lhg-fm-statements：三表搭建顺序与纪律

> 目标：从假设表出发，搭出一套"每个数字都能追溯到假设"的三表。核心纪律：**先利润表，再资产负债表，最后现金流量表；手工数必须标注**。
> 前置：lhg-fm-assumption 的 `assumptions.csv` 已就绪。

## 1. 何时使用

- 假设表已定，要出三表 → 全流程
- 用户已有三表，想复核 → 跑第 5 步（搭建自查）
- 三表不平 → 先去 lhg-fm-reconcile 查勾稽，不是本 skill 的问题

## 2. 搭建顺序（为什么是这个顺序）

1. **利润表（IS）先行**：收入是 driver，所有假设（增速/毛利率/费用率）都直接作用在利润表上。
2. **资产负债表（BS）次之**：需要利润表的净利润（进留存收益）；资产项按"收入驱动"或"手工输入"填。
3. **现金流量表（CF）最后**：净利润是起点，调增减项来自 BS 的变动。

顺序反了会怎样：先搭 BS 再搭 IS，净利润对不上留存收益时，你分不清是假设错了还是公式错了。

## 3. 利润表搭建（IS）

从收入一行行往下算，公式固定：

```
营业收入（= 上年收入 × (1 + revenue_growth)）
− 营业成本（= 收入 × (1 − gross_margin)）
= 毛利润
− 期间费用（= 收入 × opex_rate）
= 税前利润
− 所得税（= 税前利润 × tax_rate，税前利润为负时所得税为 0）
= 净利润
```

**纪律**：
- 税前利润为负 → 所得税记 0，不许算出"负的税"。
- 费用率是"期间费用/收入"，别把营业成本又算一遍（新手最常见的 double count）。
- 非经常性损益（卖资产、补贴）单独列一行，不许混进营业利润。

## 4. 资产负债表搭建（BS）

分三块，记住每块的"驱动方式"：

| 块 | 项目示例 | 驱动方式 |
|---|---|---|
| 资产 | 现金、应收账款、存货、固定资产 | 现金最后倒挤；应收/存货按"收入×周转天数/365"或手工输入；固定资产=上年+资本开支−折旧 |
| 负债 | 应付账款、借款 | 应付按成本×天数/365；借款按实际还款计划手工输入 |
| 权益 | 股本、留存收益 | 股本一般不变；**期末留存收益 = 期初留存收益 + 净利润 − 现金分红**（勾稽核心） |

**平表铁律**：每年**总资产必须等于总负债 + 股东权益**。不平的原因按概率排序：①留存收益没更新 ②现金是拍的不是倒挤的 ③分红记了两次。修复手册见 lhg-fm-reconcile。

## 5. 现金流量表搭建（CF，间接法）

以净利润为起点：

```
净利润
+ 折旧摊销（非现金费用加回）
−/+ 营运资本变动（应收/存货增加为减，应付增加为加）
= 经营活动现金流
− 资本开支
= 投资活动现金流（简化：只有资本开支时）
+/− 借款变动 − 分红
= 筹资活动现金流
```

**勾稽**：经营+投资+筹资 = 现金净增加额 = 期末现金 − 期初现金。两头对不上，先查营运资本变动的符号（新手 90% 错在这里）。

## 6. statements.csv 格式

表头：`表,项目,年,值`

```csv
表,项目,年,值
IS,营业收入,2026,10000
IS,净利润,2026,2250
BS,总资产,2026,7400
BS,总负债,2026,2500
BS,股东权益,2026,4900
CF,经营活动现金流,2026,1200
CF,现金净增加额,2026,700
```

**项目命名纪律**：同一项目每年同名（如一直叫"营业收入"，不许一年叫"营收"一年叫"销售收入"），否则审计脚本认不出来。

## 7. 搭建自查清单

- [] 利润表每行公式可追溯到假设（收入/毛利率/费用率/税率）？
- [] 税前为负时所得税为 0？
- [] 留存收益滚动公式正确（含分红）？
- [] 每年资产 = 负债 + 权益？
- [] 现金流两头勾稽（净增加 = 三项之和 = 期末−期初）？
- [] 手工输入的数字都标注了"手工输入"？
- [] 项目命名每年一致？

## 8. 反模式（不许这么干）

- ❌ 现金拍一个数，不倒挤（BS 必不平）
- ❌ 分红在利润表和 BS 各扣一次
- ❌ 营运资本变动符号搞反（应收增加写成加项）
- ❌ 为了平表，手工改一个"调节项"凑数
- ❌ 项目命名每年换一个花样
- ❌ 预测期拉到 10 年还每年给精确数字（5 年是上限，第 4~5 年给区间）

## 9. 常见问题

- **Q：第 1 年用实际数还是预测数？** A：有实际数用实际数（标注"实际"），预测从第 2 年开始。实际数是锚。
- **Q：折旧怎么定？** A：固定资产×折旧率，或按资本开支的一定比例估计并标注。折旧影响利润不影响现金，别漏了加回。
- **Q：轻资产公司（没什么固定资产）？** A：capex_rate 可以很小，但别写 0；BS 资产侧以现金和应收为主，照样要平。
- **Q：要不要做 DCF？** A：用户要估值才做。DCF 表单独放（`表=DCF`），别混进三表；折现率用 assumptions.csv 的 discount_rate。
- **Q：模型给投资人看？** A：可以，但交付时必须带"局限性声明"：假设变了结论就变；敏感性分析（lhg-fm-sensitivity）必须附上。
- **Q：多家门店/多产品线，怎么搭？** A：先每家店/每条线单独搭 IS（收入成本费用），再合并。合并时内部交易要抵消，别重复算收入。
- **Q：statements.csv 越来越大，难维护？** A：按年拆 sheet 或拆文件（如 statements-2026.csv），审计脚本支持目录扫描。命名保持 `statements-*.csv`。
- **Q：要不要在 CSV 里写公式？** A：不写。CSV 只存数值结果，公式逻辑写在模型说明里。想保留公式用 xlsx，见 lhg-excel。
- **Q：预测期 5 年，每年都要全套三表？** A：对。每年都是完整的 IS/BS/CF 行，勾稽按年验。第 4~5 年数字可以给区间（如"收入 1400~1600 万"），但勾稽用区间中点验，并在说明里注明。
- **Q：IS 和 BS 的"年"对不上（一个自然年一个财年）？** A：统一口径，二选一，并在模型说明第一行写明。口径混用是勾稽灾难的源头。

## 11. 自检与反馈

**质检门**：
- [] 搭建顺序是 IS→BS→CF？
- [] 审计脚本 blocker 为 0？
- [] 手工数全部标注？
